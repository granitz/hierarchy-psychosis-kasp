# Data directory

Nothing in here is committed except this file and the clinical CSV template
(see `.gitignore`). The analysis code resolves every path relative to this
directory, or to whatever `KASP_DATA` points at:

```bash
export KASP_DATA=/path/to/your/data
```

Run `python config.py` to print the resolved paths and see which are missing.

## Expected layout

`KASP_DATA` points at the **project root** — the directory that directly
contains the subject lists and the `results/` and `data/` folders:

```
<KASP_DATA>/
├── subjects_ctrl_clean_good_coverage.mat   scan identifiers, controls
├── subjects_sz_clean_good_coverage.mat     scan identifiers, patients
├── is_med.mat                              0/1 per patient, aligned with the above
├── results/
│   ├── results_subject_refinement/         per-subject model fits  <- the main input
│   │   ├── no_grid_subjectRefinement_group-ctrl_tau-1_med-0.mat
│   │   ├── no_grid_subjectRefinement_group-sz_tau-1_med-0.mat
│   │   └── no_grid_subjectRefinement_group-sz_tau-1_med-1.mat
│   └── results_group_only/                 group-level fits (optional)
└── data/
    ├── tseries_2/                          JSON sidecars (MeanAtlasTSNR)
    │   └── mat_files/                      parcellated BOLD, one .mat per scan
    ├── MOTION/                             confound .tsv, one per scan
    ├── derived_data/                       FC_ctrl.mat, FC_sz-0.mat, FC_sz-1.mat
    ├── clinical/                           de-identified clinical table (create this)
    │   └── clinical_data.csv
    └── atlas/
        └── parcel_centroids.csv            x,y,z per parcel — only for the
                                            spatial-autocorrelation analysis
```

Note that the JSON sidecars sit one level **above** the `.mat` timeseries,
which is why `TS_DIR` and `TSNR_DIR` are separate settings.

Check the resolution before running anything:

```bash
export KASP_DATA=/path/to/proj
python config.py
```

Every directory can be redirected individually if your layout differs:
`KASP_RESULTS`, `KASP_GROUP_RESULTS`, `KASP_TIMESERIES`, `KASP_TSNR`,
`KASP_MOTION`, `KASP_DERIVED`, `KASP_CLINICAL`.

## File contents

**Subject-refinement results** (produced by `matlab/run_hopf_subject_refinement.m`)
contain, per group:

| Variable | Shape | Meaning |
|---|---|---|
| `Ceff_Subj` | (n_subjects, 371, 371) | generative effective connectivity, fitted parcels only |
| `Ceff_Subj_full` | (n_subjects, 416, 416) | the same, NaN-padded to the full parcellation |
| `hierarchicallevels_full` | (n_subjects, 416) | trophic levels, NaN at excluded parcels |
| `trophiccoherence` | (n_subjects, 1) | directedness |
| `fittFC_subj`, `fittCOVtau_subj` | (n_subjects,) | model fit to FC and to time-shifted covariance |

Parcel order is **subcortex first** (16 Melbourne S1 parcels), then 400
Schaefer cortical parcels, so cortical maps are `x[16:]`.

**Timeseries** `.mat` files contain a variable `ts` with parcels along the
first axis. Filenames follow
`<scan-id>_task-rest_run-1_feature-corrMatrixICA24Motion_atlas-SchaeferTian416_timeseries.mat`.

**Motion** files are the confound regressor tables written by the
preprocessing pipeline, named
`<scan-id>_task-rest_run-1_setting-preproc_desc-confounds_regressors.tsv`.
Only the `framewise_displacement` column is used.

**Parcel centroids** must be a CSV with columns `x,y,z` in millimetres, one
row per parcel in parcellation order. Only the spatial-autocorrelation
analysis needs this.

**Clinical table**: generated by `scripts/00_build_clinical_table.py`, which
reads the study registry exports in `CLINICAL_DIR` and writes
`clinical_data.csv` beside them:

```bash
python scripts/00_build_clinical_table.py --dry-run   # report only
python scripts/00_build_clinical_table.py
```

It joins the scan-mapping workbook (patients on the `Patienter` sheet,
controls on `Kontroller`, which use different identifier formats) with the
demographic, PANSS and GAF/CGI exports, keys the result on the scan
identifier and drops the clinical identifier along with dates, birth years,
handedness and education. Only the columns listed in the template are
written. See `clinical_data_TEMPLATE.csv` for the layout, and
`kasp.data.load_clinical` for how it is read. It must be keyed on the scan
identifier only — no names, dates, personal numbers, free text or any other
direct identifier.
